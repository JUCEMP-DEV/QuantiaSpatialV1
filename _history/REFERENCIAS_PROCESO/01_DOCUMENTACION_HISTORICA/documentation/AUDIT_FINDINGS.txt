PROBLEMAS DE ESTRUCTURA
1. Versiones históricas ZIP mezcladas con el paquete ejecutable.
2. A1.5/A1.6 Recovery mezclado con el baseline aunque no fue validado como mejora.
3. 155 archivos .pyc dentro del árbol entregable.
4. 26+ MB de outputs de pruebas dentro de tests/output y más evidencia en cases/output.
5. Duplicados de pruebas con sufijo '(1)'.
6. phase_04_rooms / phase_05_validation / phase_06_contract conservan imports a
   phase_02_boundaries.boundary_models, módulo que ya no existe en la base actual.
7. test_quantia_spatial_proposal_c_miguel_v.py dependía de un test F03 legacy para
   funciones auxiliares; en el paquete reorganizado quedó autocontenido.

DECISIÓN
Separar runtime, pruebas vigentes y documentación histórica. El runtime vuelve al
checkpoint Proposal C A1.2, que es el punto de Candidate Discovery utilizado para
identificar el problema real de clasificación/exclusión.
